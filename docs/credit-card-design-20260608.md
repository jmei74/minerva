## 一、背景

### 1.1 市场洞察

新加坡主流高端信用卡（DBS Altitude、Citi PremierMiles、HSBC TravelOne 等）的核心差异化之一是**机场贵宾室权益**：

| 卡片 | 贵宾室网络 | 免费次数/年 | 年费（S$） |
|------|-----------|------------|-----------|
| DBS Altitude | Priority Pass | 2次通行证 | 196.20 |
| Citi PremierMiles | Priority Pass | 2次/年 | 196.20 |
| HSBC TravelOne | Mastercard Travel Pass | 4次/年 | 196.20 |
| CIMB Founders Card | Mastercard Travel Pass | 无限次 | 待核实 |
| AMEX Explorer | 环亚贵宾室 | 10次/年 | 179.85 |

市场趋势：
- **CIMB Founders Card（2025年9月）** 开创性地推出"无限次免费贵宾室"，打破高端卡年费门槛
- 新加坡无现金渗透率全球前三（87%），高端信用卡用户对出行体验要求高
- MAS 推动无现金支付（2025年底停发公司支票），信用卡消费场景持续扩大

### 1.2 用户痛点

当前高端信用卡用户在使用贵宾室权益时普遍面临以下问题：

1. **权益不透明**：用户不清楚自己有多少次免费贵宾室使用权、还剩几次
2. **入场流程繁琐**：需出示实体卡+登机证，现场核验效率低
3. **贵宾室信息缺失**：不知道附近有哪些贵宾室、营业时间、设施（淋浴/Wi-Fi/餐饮）
4. **带人费用不清晰**：同行亲友收费标准不明确，导致现场纠纷
5. **权益过期风险**：Priority Pass 年度会籍过期前没有主动提醒

### 1.3 设计目标

设计一个**智能贵宾室权益管理系统（Lounge Benefits Management System）**，作为信用卡 App 的高端用户专属模块，参考新加坡 CIMB Founders Card（无限次贵宾室）和 DBS Altitude（Priority Pass + 2次通行证）的权益模型。

## 二、功能描述

### 2.1 核心功能矩阵

| 功能 | 描述 | 用户价值 |
|------|------|---------|
| **F1. 权益总览看板** | 展示用户当前贵宾室剩余免费次数、有效期、关联卡号 | 消除权益不透明问题 |
| **F2. 贵宾室查找与导航** | 基于当前位置/航班信息，查找附近可用贵宾室（含设施/营业时间/评分） | 提升出行体验 |
| **F3. 电子通行证入场** | 生成动态 QR 码，替代实体卡+纸质登机证，扫码入场 | 简化入场流程 |
| **F4. 权益到期提醒** | 距权益过期前 7 天推送提醒，支持一键续期 | 减少权益浪费 |
| **F5. 带人费用预估** | 展示带亲友入场的大致费用，支持 App 内提前支付 | 避免现场纠纷 |

### 2.2 用户场景示例

**场景：Lee，商务人士，持有一张 DBS Altitude Visa Signature（Priority Pass + 2次/年免费通行证）**

- 6月15日，他将乘新航飞往香港 → App 首页自动显示「您的 Priority Pass 还有 2次免费使用权，距到期还有 45 天」
- 6月15日当天，他打开 App 查看新加坡机场贵宾室 → App 展示 T1 环亚贵宾室（距登机口 35，淋浴/Wi-Fi/热餐，评分 4.2/5，当前客流低）
- 他点击「生成入场码」→ App 生成动态 QR 码（5分钟刷新一次，有效期 2 小时）→ 在贵宾室入口扫码入场
- 他的同事临时想一起进入 → App 显示「同行人员：约 S$32/位」，他一键支付，同事也获准入场
- 6月28日，他的 2 次通行证已用完 → App 推送「您的免费贵宾室通行证已用完，购买额外次数（2次 S$64）」

### 2.3 差异化设计亮点

1. **Pre-flight 自动权益提醒**：用户购票/值机后，App 自动推送贵宾室权益提醒（新加坡现有 App 均无此功能）
2. **动态 QR 码**：安全性高于静态卡号展示，防止截屏滥用（参考新加坡 SingPass 动态码设计）
3. **权益与航班联动**：关联用户行程，自动推荐登机口附近的贵宾室，减少误机风险
4. **多卡权益整合**：支持同一用户多张高端卡权益统一管理（如同时持有 AMEX + DBS Altitude，自动推荐最优卡）

### 3.2 与现有架构的集成

本服务作为**独立微服务**部署，与现有 architecture-design.md 中的服务集成：

| 现有服务 | 集成方式 | 说明 |
|---------|---------|------|
| Account Service | REST 调用 | 验证账户状态、卡种、贵宾室权益等级 |
| Transaction Service | Kafka Event | 通行证使用记录写入交易流水（EVENT: LOUNGE_ACCESS） |
| Notification Service | REST 调用 | 触发权益到期提醒、行程联动提醒 |
| Credit Engine | — | 贵宾室权益不涉及额度，暂不集成 |

### 3.3 关键模块说明

#### 3.3.1 权益管理模块

- **输入**：account_id → 查询账户卡种 → 匹配贵宾室权益规则
- **权益规则配置化**（按卡种）：
  ```json
  {
    "card_type": "DBS_Altitude_Visa_Signature",
    "lounge_network": "Priority_Pass",
    "free_access_count": 2,
    "count_reset_period": "ANNUAL",
    "同行人员费率": "S$32/人",
    "access_method": "QR_CODE"
  }
  ```
- **权益次数扣减**：每次入场（QR scan）触发 `LOUNGE_ACCESS` 事件，扣减次数

#### 3.3.2 动态 QR 码生成

- **技术方案**：JWT 签名二维码，5 分钟刷新一次
- **JWT Payload**：
  ```json
  {
    "account_id": "uuid",
    "card_last4": "1234",
    "lounge_network": "Priority_Pass",
    "valid_from": "2026-06-15T08:00:00Z",
    "valid_until": "2026-06-15T10:00:00Z",
    "signature": "HMAC-SHA256"
  }
  ```
- **验证流程**：贵宾室入口扫码 → 服务端验证 JWT 签名 + 时间窗口 + 权益状态

#### 3.3.3 第三方贵宾室 API 对接

| 供应商 | API 功能 | 对接成本（Elaine 研究估算） |

| Priority Pass API | 会员验证 + 使用记录 | S$40-80K |

> 注：Phase 1 MVP 可先不接入第三方 API，使用本地数据库存储贵宾室基础信息（覆盖新加坡/香港/曼谷主要机场），降低初期开发成本。

## 六、风险提示

| 风险 | 级别 | 缓解措施 |
|------|------|---------|
| **QR 码被截图滥用** | 🔴 高 | JWT 签名 + 5 分钟刷新 + 入口扫码时校验时间窗口，SingPass 同款方案 |
| **Priority Pass API 对接复杂度** | 🟡 中 | Phase 1 使用本地数据，Phase 3 再对接，参考 DBS 现有对接方案 |
| **贵宾室信息不准确**（营业时间/设施变更） | 🟡 中 | 与第三方 API 实时同步 + 用户反馈机制，定期更新数据 |
| **多卡权益冲突**（同一用户多张卡均有贵宾室权益） | 🟡 中 | App 自动推荐最优卡（剩余次数最多/覆盖当前机场），用户可手动切换 |
| **贵宾室客流超载**（免费次数导致大量用户涌入） | 🟡 中 | 实施名额管理（参考银联钻石卡每日 100 名额模式）+ 动态定价引导 |
| **MAS 合规要求**（贵宾室权益披露条款） | 🟡 中 | 参考《银行服务收费基准清单》设计权益说明页面，符合透明披露要求 |

## 七、合规与监管考量

- **MAS 监管**：贵宾室权益属于信用卡附加服务，《银行服务收费基准清单》要求明确权益条款和限制
- **PCI-DSS**：QR 码不含完整卡号，仅存储后 4 位 + JWT 签名，符合 PCI-DSS 数据最小化原则
- **个人数据保护法（PDPA）**：贵宾室使用记录（含位置信息）属于个人数据，需明确用户同意机制
- **跨境数据**：若扩展至东南亚其他国家（马来西亚/泰国），需符合各国数据本地化要求（BNM/BOT 框架）
