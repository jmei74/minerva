1. 架构设计原则

强一致性优先
账务数据零差错，TPS ≥ 3000 可用异步写流水 + 幂等补偿实现
安全红线不妥协
PCI-DSS 合规贯穿所有层级，从数据加密到日志脱敏
最小可行架构
不引入过度设计，Phase 1 验证后再迭代
性能有数据再动
瓶颈定位后才优化，避免 premature optimization

3. 微服务职责边界

3.1 Account Service（账户管理服务）

模块说明
AccountController开卡 / 销户 / 账户查询 / 状态变更
LimitManager永久额度 / 临时额度调整（含审批流触发）
AccountStatusMachine状态机：PENDING → ACTIVE → FROZEN → CLOSED

API： POST /api/v1/accounts 创建账户 · GET /api/v1/accounts/{id} 查询 · PUT /api/v1/accounts/{id}/limit 额度调整 · PUT /api/v1/accounts/{id}/status 状态变更

3.2 Transaction Service（交易处理服务）

模块说明
AuthorizationHandler联机授权 / 预授权 / 授权完成 / 授权撤销
TransactionProcessor消费确认 / 还款 / 退货 / 冲正
IdempotencyManager幂等键管理（防重复扣款）

核心链路约束：P99 < 100ms，先查 Redis 额度 → 乐观锁更新 DB → 异步写 Kafka

3.3 Billing Service（账单服务）

模块说明
StatementGenerator批量账单生成（XXL-Job 触发，10 万账户 < 30 分钟）
InterestCalculator全额计息 / 分期计息（配置化，支持热更新）
LateFeeProcessor滞纳金计算

3.4 公共能力层

组件核心职责
Credit Engine可用额度 = 固定+临时-已用-冻结；实时计算 / 扣减 / 释放 / 预授权管理
Pricing Engine取现手续费、利息（全额从消费日起）、滞纳金、分期手续费
Event BusKafka Producer / 消息路由

4. 服务间通信方案

场景方式理由
实时授权决策同步 REST/gRPC100ms 内需响应
交易流水落库异步 Kafka高并发写入，削峰填谷
批量任务触发异步 XXL-Job → Kafka账单/计息按批次
跨服务状态同步异步 Kafka Event账户状态变更通知下游
超时敏感场景Hystrix / Sentinel 熔断下游不可用时降级

Kafka Topics： credit-card.transaction.events（交易事件） · credit-card.account.events（账户事件） · credit-card.billing.events（账单事件） · credit-card.credit.events（额度事件） · credit-card.dlq（死信队列）

5. 数据库表结构设计

共 9 张表，PostgreSQL 16，主从 + 读写分离。

表名用途关键设计
account信用卡账户可用额度计算字段（GENERATED STORED），乐观锁 version，card_no AES-256 加密
transaction交易流水idempotency_key UNIQUE 防重复，auth_code 索引（WHERE NOT NULL）
authorization授权记录预授权 / 授权完成，expire_time 索引清理过期预授权
installment分期记录消费分期 + 账单分期，覆盖分期本金 / 期数 / 手续费率
installment_schedule分期还款计划UNIQUE(inst_id, period)，due_date 索引批量扣款
bill账单UNIQUE(account_id, bill_month)，含上期最低额未还字段
bill_item账单明细关联交易流水，含消费日期/商户/金额
credit_limit_adjustment额度调整记录审批流 ID，PERMANENT / TEMP 类型
audit_log操作审计按月分区（PARTITION BY RANGE），保留 7 年（84 个分区）
-- 账户表（含可用额度计算字段 + 乐观锁）
CREATE TABLE account (
    account_id          UUID PRIMARY KEY,
    customer_id         UUID NOT NULL,
    card_no_encrypted   VARCHAR(256) NOT NULL,      -- AES-256 加密存储
    card_no_last4       CHAR(4) NOT NULL,            -- 仅后 4 位明文
    credit_limit        DECIMAL(15,2) NOT NULL,
    temp_limit          DECIMAL(15,2) NOT NULL DEFAULT 0,
    used_amount         DECIMAL(15,2) NOT NULL DEFAULT 0,
    frozen_amount       DECIMAL(15,2) NOT NULL DEFAULT 0,
    available_amount    DECIMAL(15,2) GENERATED ALWAYS AS (
                            credit_limit + temp_limit - used_amount - frozen_amount
                        ) STORED,
    over_limit_ratio    DECIMAL(5,4) NOT NULL DEFAULT 0.1000,
    status              VARCHAR(20) DEFAULT 'ACTIVE',
    version             BIGINT NOT NULL DEFAULT 0,   -- 乐观锁
    open_date           DATE NOT NULL,
    created_at          TIMESTAMP NOT NULL DEFAULT NOW(),
    updated_at          TIMESTAMP NOT NULL DEFAULT NOW()
);
-- 分期表（补全 PRD 中缺失的实体）
CREATE TABLE installment (
    installment_id       UUID PRIMARY KEY,
    account_id           UUID NOT NULL REFERENCES account(account_id),
    installment_type    VARCHAR(20) CHECK (installment_type IN ('PURCHASE', 'BILL')),
    principal           DECIMAL(15,2) NOT NULL,         -- 分期本金
    total_installments  SMALLINT NOT NULL,            -- 总期数
    completed_installments SMALLINT DEFAULT 0,
    installment_amount  DECIMAL(15,2) NOT NULL,      -- 每期还款金额
    fee_rate            DECIMAL(5,4) NOT NULL,          -- 手续费率（月）
    total_fee           DECIMAL(15,2) NOT NULL,       -- 总手续费
    monthly_payment     DECIMAL(15,2) NOT NULL,      -- 每月应还（本金+手续费）
    first_due_date      DATE NOT NULL,
    status              VARCHAR(20) DEFAULT 'ACTIVE',
    start_date          DATE NOT NULL,
    created_at          TIMESTAMP DEFAULT NOW()
);

6. Redis 缓存策略

Key Pattern类型TTL用途
credit:snapshot:{account_id}Hash5s额度快照（实时性要求高）
credit:available:{account_id}String5s可用额度计算值
auth:idempotency:{key}String24h幂等键（防重复扣款）
auth:pending:{auth_code}Hash30d预授权信息
lock:account:{account_id}String10s分布式锁（额度更新）
rate:limit:{client_id}String1min令牌桶限流计数器

额度快照一致性：Cache-Aside 模式，Redis 与 DB 不一致时以 DB 为准。TTL 5s 强制回源。

9. 安全设计（PCI-DSS 合规）

控制项实现措施
数据加密card_no：AES-256-CBC（KMS 管理密钥，90 天轮转）
传输加密全链路 TLS 1.3（Gateway → Service → DB/Redis/Kafka）
访问控制mTLS（服务间）+ JWT（外部 API）
审计日志所有写操作写 audit_log 分区表，保留 7 年
卡号掩码日志 / API 响应中禁止明文卡号
漏洞扫描每季度 OWASP Top 10；每年一次渗透测试

10. 技术决策记录（ADR）

ADR-001
授权链路用 Redis 快照判断额度
高并发避免 DB 瓶颈，P99 < 100ms
⚠️ Redis 与 DB 不一致 → 5s TTL + Cache-Aside 缓解
ADR-002
交易流水异步写 Kafka
交易成功即返回，流水异步落库削峰
⚠️ 消息丢失风险 → acks=all + 手动提交缓解
ADR-003
幂等键存 Redis TTL 24h
防重复扣款，轻量实现
⚠️ Redis 不可用 → 降级 DB 查询幂等键
ADR-004
账单批量生成用 XXL-Job
任务可视化，支持 HA
⚠️ 10 万账户需优化批量 SQL
ADR-005
分期占用计入 frozen_amount
额度模型统一，计算简单
⚠️ 分期提前结清需主动释放额度
ADR-006
使用 Kong API Gateway
性能优于 Java Gateway，插件生态好
⚠️ Lua 插件开发需额外投入
ADR-007
PG 乐观锁更新额度
避免分布式锁性能损耗
⚠️ 热点账户冲突重试，最多 3 次
